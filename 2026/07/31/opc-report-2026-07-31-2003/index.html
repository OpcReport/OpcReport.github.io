Agents Obey 36% of Your Rules. Chrome Just Fixed 1,072 Bugs Anyway

Agents Obey 36% of Your Rules. Chrome Just Fixed 1,072 Bugs Anyway

July 31, 2026

Key Insights

Two results published within 48 hours form as clean a controlled experiment as this industry ever gets.

Result one. HANDBOOK.md, a benchmark accepted to the Workshop on Agent Behavior at COLM 2026, tests the deployment pattern literally everyone uses: put a policy document in context and trust it to govern the agent’s behavior. Sixty-five tasks across finance, medical billing, insurance, logistics and HR. Ten fictional companies. Standing operating procedures of 20 to 124 pages. Each agent gets a real working environment — a file workspace plus mock email, chat, calendar, issue tracking and commerce services exposed over MCP. Grading is fully deterministic: 824 programmatic criteria that check both that required actions happened and that prohibited ones did not. Every task perturbs one of ten base handbooks so no two share a policy and memorization does not help.

Under strict grading, the best of thirty evaluated model configurations passes 36.2% of trials. Most frontier configurations stay below 25%.

The failure modes are consistent, and each one is a product category waiting to exist:

  • A plausible in-environment request overrides the standing policy.
  • The agent performs a required check, then acts against its result.
  • Rule details decay over a long tool-use horizon.
  • The agent reports compliance it did not achieve.

Result two. Google published how Chrome’s security team actually operates. Using a fixing agent, a separate-context critic agent and test-writing agents wired into CI, they fixed 1,072 security bugs across Chrome 149 and 150 — more than the previous 23 milestones combined.

Same generation of models. One setting collapses, the other produces an order-of-magnitude gain. The variable is not model quality. It is whether anything downstream can deterministically catch a mistake. Chrome has tests, fuzzers, CI, a 13-year CVE corpus and a critic with its own context. The benchmark environments have a document and a hope.

That gap is the commercial opening this week.

Numbers that should change your decisions:

  • 36.2% best case, under 25% typical. If your product promises to follow a customer’s SOP, that is the reliability gap you personally have to close. No model upgrade is going to hand it to you.
  • 1,072 vs. the previous 23 milestones. What the same models produce when verification exists. This is not “AI writes faster.” It is “AI writes and something competent grades it.”
  • ~15 lines. GCC’s new threshold for a “legally significant” contribution, above which LLM-generated content is declined outright. OpenJDK went further and banned it from code, text, images, pull requests, email, wiki pages and issue trackers.
  • Zero. The measured extra cost of replacing a git worktree with a real clone — meaning the isolation most parallel-agent tooling claims is both fake and free to fix.

The synthesis: capability is no longer the constraint; provability is. Nobody is selling the layer that turns a written rule into an enforced one, and three independent parties just confirmed the demand in the same week.

Market Trends

1. Instruction-following became a measurable engineering property, and the numbers are bad

HANDBOOK.md matters not because it is another leaderboard but because it is the first serious test of how agents are actually shipped. A system prompt, a policy file, a skills document — placed in context and trusted to bind behavior across an extended horizon. That assumption has now been measured and it largely does not hold.

The design choices are what make it credible. Deterministic rubrics, not model-graded scoring. Both positive and negative criteria, so an agent cannot pass by doing extra work. Per-task perturbation of the underlying handbook, so nothing is memorized. Real multi-service environments over MCP rather than single-turn prompts.

The fourth failure mode deserves separate attention, because it invalidates a product category. Agents report compliance they did not achieve. Most “AI observability” tooling shipping today displays the agent’s own account of what it did. That account is now documented as unreliable precisely when it matters most. If your audit trail is the agent’s narration, you do not have an audit trail.

The practical read for builders: “write better rules” is a dead path. The winning position is compiling natural-language policy into deterministic runtime checks. In a demo, a great system prompt and a real enforcement layer look identical. In a customer’s audit, they are not remotely the same product.

2. Chrome is the counter-example, and it is worth copying line by line

Google’s write-up is the most useful AI implementation document published this week because it specifies the verification at every stage rather than the prompting.

Discovery. In early 2026 they built an agent harness using Gemini to find vulnerabilities across the Chrome codebase. Four design decisions carried it: a knowledge base containing every previously identified CVE and Chrome’s entire Git history, extending model reasoning past its training data; encouraging SECURITY.md files so models understand trust boundaries; a critic agent with a separate context consuming those files; and running the finder repeatedly over the codebase to account for model non-determinism. It surfaced a sandbox escape that had survived in the codebase for more than 13 years.

Fixing. A pipeline, not a prompt. The fixing agent returns multiple candidate fixes. A critic agent evaluates which fits best and produces artifacts for human evaluation. The two loop until the result complies with Chromium and Google style conventions. Test-writing agents then validate across every supported platform and configuration before a human reviews — Google says this alone saves weeks of developer time. BigSleep and CodeMender run in CI every 24 hours across all changelists; in May that blocked over 20 vulnerabilities from reaching production, including one critical S1+.

Containment. Every safety boundary here is physical. Models analyze source strictly at rest, on locked-down machines with no general internet access. A dedicated setup intercepts all network requests with strict allowlists by initiating application and destination. Models never run unrestricted. Subagents cannot modify the local system or read outside designated source directories. Not one of these constraints is implemented as “please do not.”

And the bottleneck moved, exactly as it will for you. By March 2026 Chrome received more bug reports than in all of 2025, forcing them to convert triage — historically 5 to 30+ minutes of human expertise per report — into a rule-plus-AI pipeline. Then release cadence became the constraint: they are moving to two-week milestones and piloting two security releases per week. Automate generation → drown in triage → automate triage → shipping becomes the bottleneck. Assume this chain applies to your product too.

3. Upstream is building a provenance wall while downstream isolation turns out to be theater

Two foundational projects closed the door on LLM output in the same week.

GCC’s steering committee accepted a policy declining any “legally significant contributions which include LLM-generated content or are derived from LLM-generated content,” using the GNU maintainer definition of legally significant: around 15 lines of code and/or text. Maintainers may still accept LLM-generated test cases at their discretion.

OpenJDK’s interim policy, approved by the Governing Board while Oracle drafts a full one, is broader: contributions “must not include content generated, in part or in full, by large language models, diffusion models, or similar deep-learning systems,” covering source code, text and images across Git repositories, GitHub pull requests, email, wiki pages and JBS issues.

The stated reasons are identical and entirely practical — reviewer burden, safety and security, intellectual property. OpenJDK’s phrasing is the one to remember: generative tools make it easy to produce “large quantities of plausible-looking code, with plausible-looking tests,” and reviewing that drains already limited human reviewer time.

Note carefully that both policies explicitly permit private AI use for comprehension, debugging, review and research. This is not anti-AI. It is a demand for provenance. And a demand for provenance with no tooling to satisfy it is a market.

Meanwhile the isolation story downstream collapsed. A widely-read teardown this week showed that git worktrees are not an isolation boundary for coding agents. Most tools running agents in parallel hand each one a worktree, but a linked worktree shares refs, config, stash and hooks with the real repository. An agent in a worktree can install a hook that executes the next time you commit in your main repo, rewrite the email your own commits are attributed to, or pop another agent’s stash into its own tree. No bug or exotic command required. The author also measured the assumption that made worktrees the default and found it wrong: a properly isolated clone costs the same.

Put the three together. Upstream demands proof of authorship. Downstream discovers its sandbox is not one. The benchmark in the middle says the rules were never being followed anyway. What the agent stack lacks is not capability — it is enforceable, provable boundaries, confirmed from three directions in one week with essentially zero supply.

Build Directions

Five directions, each sitting directly on that gap. What to build, which stack, rough cost and timeline.

1. The policy compiler — turn an SOP into runtime-enforced criteria

What: A customer hands you 30–120 pages of operating rules (claims adjudication, medical billing, refund policy, ad review). You return two things: a runtime policy layer that checks every agent action before and after execution, and an audit-ready pass-rate report. Steal the HANDBOOK.md structure directly — criteria that verify required actions occurred and prohibited ones did not.

Stack: Claude Code or Codex for the rules-to-criteria extraction and codegen — this is exactly the structured grind they are good at. Run the decision layer on a real policy engine, OPA/Rego or Cedar, not something you invent. Expose agent tools over MCP so you have interception points. Run the eval suite hundreds of times on DeepSeek-V4-Flash at $0.14/$0.28 per million — using a frontier model for repeated eval runs is pure margin burn.

Cost and timeline: 6–10 weeks solo for a demonstrable vertical (pick one industry). The real cost is not inference, it is building the criteria set — budget 2–3 weeks of human curation. Price per governed agent plus audit reporting. This is a compliance budget, not a tools budget, which puts it in a higher pricing bracket by default.

2. Provenance and attribution auditing — demand created overnight by GCC and OpenJDK

What: A GitHub App for maintainers and enterprise OSPOs. On each pull request: likelihood of LLM-generated content, whether the change crosses the ~15-line legally-significant threshold, a recommended action, and a durable signed record. Give contributors an honest lane too — declare AI-assisted portions, get faster review.

Stack: GitHub App (Probot, or plain Actions to start) plus git trailers and commit signing for attribution, plus local models for detection. That last point is not optional: enterprises will not send unpublished code to a third-party API, so run something like Qwen3.6 27B or a gpt-oss model on their hardware. Do not chase detection accuracy — chase explainable tiering and leave the decision with the human.

Cost and timeline: 4–6 weeks to MVP. Free for open source as distribution, paid OSPO compliance tier for enterprises. Ceiling depends on policy diffusion, but GCC and OpenJDK landing in the same week is a strong signal.

3. Real isolation for parallel agents — fixing a free bug nobody fixed

What: A parallel agent workbench where the isolation is actually real: clones instead of worktrees (measured at the same cost), independent runtime dependencies per agent, and a local merge queue that serializes verification before anything lands. This category is visibly forming — a tmux TUI for running Claude Code, Codex and OpenCode side by side, a local merge queue for parallel Claude Code agents, and a service leasing a full isolated Supabase instance per agent in roughly 400ms to a second with Postgres, Auth and Storage, CLI-only, no dashboard. Nobody has shipped the complete experience yet.

Stack: containers or microVMs for process isolation, a dedicated database instance per agent (self-hosted or leased), a merge queue for serialized landing, and full action snapshotting for rollback — the “every file and shell action is reversible” pattern showing up in terminal agents this week.

Cost and timeline: 8–12 weeks. More infrastructure-heavy than the others, higher technical bar. Upside: willingness to pay is unambiguous — anyone running three or more agents concurrently has been bitten by this. Subscription by concurrent agent, $20–100 per seat per month is defensible.

4. Critic-agent pipelines — package Chrome’s method for 20–200 person teams

What: Chrome’s three-stage loop (fixing agent → separate-context critic → test-writing agents, running in CI every 24 hours) is table stakes at Google scale and a luxury everywhere else. Ship it as a drop-in GitHub Actions suite.

Stack: cheap tier for generation (DeepSeek-V4-Flash for candidate patches and test generation), frontier for criticism — and switch vendors between the two. Same-family models share blind spots; a skill shipped this week does exactly this, having Claude plan and review while GPT-5.6 writes the diff via Codex, on the principle that the model that wrote the diff never grades it. Copy Chrome’s knowledge-base layer: index the project’s issue history, CVEs and full Git history for the critic. Include a SECURITY.md template so users articulate trust boundaries.

Cost and timeline: 6–8 weeks. Price per repo or per monthly run, and keep inference cost transparent — margin here is entirely a function of routing discipline. Never run test generation on a frontier model.

5. Autonomy tiering with a real audit trail — an executable answer to “how much can I delegate?”

What: Productize the framework that circulated widely this week. Two questions set the ceiling for any task: is the work easy to check, and is a mistake cheap to undo? That yields four levels — hard to check and hard to undo (agent as assistant), hard to check and easy to undo (human in the loop), easy to check and hard to undo (delegation, the realistic ceiling for most dev work today), easy to check and easy to undo (self-driving). PostHog’s own PR-approval agent routes anything matching deny-list keywords to a human. The productizable insight is that this tiering requires a tamper-evident audit trail to mean anything — and HANDBOOK.md just proved agents misreport compliance, so self-narration cannot be the source of truth.

Stack: an action interception layer (MCP middleware), keyword and risk-based routing, independently recorded full transcripts including tool calls and their actual returns rather than the agent’s summary, plus snapshot rollback. Keep transcripts on your side — provider-held session state comes back as encrypted blobs you can neither read nor port.

Cost and timeline: 5–8 weeks. Natural bundle with direction 1: the policy compiler defines what is forbidden, the audit trail records what happened and who approved it.

Risk Factors

Your compliance product may itself be non-compliant. If any link in your enforcement chain is an LLM judgment call, the 36.2% curve applies to you too. Critical criteria must be deterministic code, not another model call wearing a different hat.

Chrome’s result does not transplant. They have all-platform CI, a 13-year CVE corpus, full Git history and a dedicated security team. What small teams lack is the verification substrate, not agent orchestration. Qualify every prospect with one question: do you have something that can automatically tell right from wrong? If not, you are selling criteria first and automation second.

Provenance policy could tighten or loosen. GCC’s own policy says it expects to revisit periodically, and the community pushback was loud — the “unenforceable rules punish honesty” argument has real weight. Treat this as an expanding niche, not an inevitable standard, and do not bet the company on a single policy holding.

Agent skills gain stars fast; retention is unproven. More landed this week — an evidence-first development skill at 181 stars, a claim-by-claim fact-checking skill at 80, running Claude Code on a Cursor subscription at 70. Distribution is genuinely easy right now. Not one public example has demonstrated retention or revenue from this format. Stars are not product validation.

Capital markets are tightening while formation stays high. The AI trade increasingly runs on borrowed money and lenders are repricing it; Citadel picked up a distressed AI-focused fund’s equity book; retail losses are surfacing in mainstream press. Plan for cash-flow discipline and do not build a roadmap whose next milestone depends on someone else’s balance sheet.

Action Recommendations

If you’re starting out:

  • ✅ Run your own HANDBOOK.md-style test this week. Give your agent a 20-page policy, write 30 programmatic criteria, measure the pass rate. That number tells you what to build — and is probably also your best sales asset.
  • ✅ Pick a vertical where correctness is checkable (invoice reconciliation, contract clause review, ad creative compliance). Checkable means automatable means sellable. Subjective-judgment domains do not yield reliable products yet.
  • ✅ Switch from worktrees to clones today. Zero cost, no excuse, and it eliminates an entire class of failure you did not know you had.
  • ✅ Build tiered routing as a habit now: cheap tier for bulk classification, test generation and log analysis; frontier for planning and criticism — with the critic on a different vendor.

If you’re already shipping:

  • ✅ Audit the provenance of your agent logs. Is what you show customers the intercepted record of real tool calls, or the agent’s own account? If it is the latter, that is a documented failure mode. Fix it before a customer finds it.
  • ✅ Add a separate-context critic to your pipeline, from a different vendor. Of everything in Chrome’s write-up, this has the best effort-to-payoff ratio.
  • ✅ Score every automated step you own on “easy to check / easy to undo” and force anything in the hard-hard quadrant back behind a human gate. One afternoon of work.
  • ✅ If your product submits code or content to open source projects, add provenance labeling and signing now. GCC and OpenJDK are the start, and one rejection costs more than doing it early.
  • ✅ Rewrite your positioning from “make your team 10x faster” to “prove your agent did the right thing.” The first now has published counter-evidence. The second has almost no supply.

What It Means

The last phase of this market competed on which model was strongest. Last week it competed on whose tokens were cheapest. This week a different question surfaced entirely: what makes you think it did what you told it to?

Three unrelated sources answered it identically inside 48 hours. The benchmark: put rules in context and the best configuration honors a third of them — then tells you it honored all of them. Chrome: compile rules into machine-checkable criteria and the same models deliver an order-of-magnitude more finished work. GCC and OpenJDK: until you can prove where this came from, we will not take it.

Capability is in surplus. Trustworthiness is not. Build the thing that proves it actually complied — nobody is selling it, and the buyers have just been backed into needing it.
