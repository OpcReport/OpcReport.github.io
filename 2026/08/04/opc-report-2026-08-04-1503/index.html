Fifty Fake CVEs Got Into the NVD. Nobody Ran the Proof-of-Concept.

Fifty Fake CVEs Got Into the NVD. Nobody Ran the Proof-of-Concept.

August 4, 2026 — trend monitoring for independent builders and one-person companies

Key Insights

The headline judgment: Line up today’s top three Hacker News stories and they’re the same story from three angles.

#1 (1,723 points) is a short post titled Don’t be a meat proxy. The author is done with colleagues who paste Claude’s output verbatim into Slack and pull request threads: “I can talk to Claude myself. It’s going to be faster and I get to control the context. I don’t need a meat proxy in between.”

#3 (707 points) is JFrog’s forensic writeup. A freshly created GitHub repo pushed a batch of 50+ vulnerability advisories, several against SQLite. NVD flagged them Critical. CISA’s ADP agreed. Red Hat initially scored one at 10.0 Critical. Then JFrog tried to reproduce them and the claims dissolved: the functions cited in the advisories did not exist in the versions named. exprComputeOperands(), allegedly the site of a use-after-free in SQLite 3.41, was not added to SQLite until mid-2025. The PoC payloads did not crash anything. None of the advisories appear on SQLite’s own advisory page.

And a third post at 768 points argues that LLMs reward expertise — that Terence Tao extracts things from the same ChatGPT you use that you simply cannot.

One conclusion connects all three: generation is now commodity-priced, and judgment has not been priced at all. Code, advisories, analysis — machines mass-produce all of it. But “is this thing correct, and does it deserve a human’s attention?” has no infrastructure answering it systematically. If the NVD — a root node of global security trust — can be filled with fabricated data, assume every other trust surface in your industry is equally exposed.

The implication for a one-person company: stop building products that generate X. That lane belongs to the model vendors. Build products that prove X is correct. Reproduce, refute, attribute, score, reject. These verbs are all understaffed right now, and the customers are compelled to pay (compliance mandates, audit requirements, security policy) rather than persuaded to pay. That is a categorically better place to sell from.

Five data points that should change your decisions:

  • 50+ fabricated CVEs entered the NVD; one representative CVSS went from 10.0 to 7.6. JFrog’s audit found advisories citing non-existent functions, contradictory metadata, n/a placeholders, and line references unrelated to the claimed bug. The official CVE pipeline currently has no automated reproduce-or-reject step. That’s a visible product-shaped hole.
  • 15% for seniors, 25% for juniors. Bjorn Roche’s time-allocation breakdown: a senior engineer spends only ~1.5h/day writing new code, so even a 3x speedup on that slice saves 1.25 hours (8h → 6.75h). Juniors gain more because they code more. Writing code was never the bottleneck — which explains why teams adopt AI and don’t see output double.
  • FP8 KV cache: 686K → 1.37M resident tokens, +41% peak throughput, ~30% lower cost per token. Cloudflare’s measured numbers on Kimi K2.6. Separately, GLM 5.2 weights compressed FP8 → INT4 shrink the checkpoint from 705 GB to 421 GB with no accuracy loss (GSM8K 94.24 → 94.09). Inference keeps getting cheaper — don’t build a moat on “I run it cheaper than you.”
  • An 80B model in 4.3 GB of RAM on a Mac; 116 stars in one day. Swiftlet, written in Swift, README noting it was “built in collaboration with Claude Code.” Top HN comments applied the cold water: prefill of 10K tokens on an M5 takes close to half an hour, and the disk-swapping approach chews through SSD endurance. Right direction, wrong year.
  • $225B in hyperscaler bond issuance year-to-date, +973.7% YoY, $1.65T in hidden debt. S&P Global’s count, on pace for $400B for the full year. The only thing this number means for you: today’s API prices are debt-subsidized. Don’t model three years out assuming token costs only fall.

Market Trends

1. AI slop is now contaminating infrastructure-grade trust systems

The severity of the SQLite incident isn’t a handful of fake bugs. It’s the proof that no link in the chain performs verification. Anonymous new repo submits in bulk → NVD ingests and marks Critical → CISA’s ADP concurs → Red Hat assigns 10.0 → vulnerability scanners at thousands of companies light up red → engineers are dispatched to “fix” a bug that does not exist. Nobody in that chain ran the PoC once.

JFrog’s reproduction workflow reads like a product spec:

  1. Source inspection — clone the official sqlite/sqlite repo, check out the target tags (3.41.0, 3.51.2, 3.51.3), compare the claimed mechanics against actual source.
  2. Clean build — compile official releases inside isolated Docker containers to prevent environmental contamination.
  3. PoC execution — feed each advisory’s PoC verbatim into the compiled binary under AddressSanitizer.
  4. Metadata audit — cross-check CPE patterns across NVD and GHSA feeds.

Not one of those steps requires a PhD. All four are automatable. None of them is happening officially today.

Two HN comments name the commercial value precisely. First: “This is going to be fun for organizations that are mandated to patch all CVEs, isn’t it?” — compliance is a non-negotiable payment trigger. Second: “Not validating submissions seems like an avenue for massive attack. Flood the whole system with endless false reports, making it significantly less reliable.” — this has escalated from a noise problem to an attack surface.

The necessary counterweight, also from the thread: LLMs are finding plenty of genuine CVEs, and black hats are surely leveraging them hard. So the correct read isn’t “AI-found vulnerabilities are garbage.” It’s that the volume of mixed true-and-false is exploding while sorting capacity stays flat. Any domain where signal-to-noise is collapsing is a domain that needs a sorting tool.

2. Domain expertise became a measurable premium, not a sentiment

Sean Goedecke’s 768-point post deserves a full read. His thesis: everyone queries the same models, so “prompt engineering” isn’t a skill — the skill is depth in the domain you’re prompting about. His exhibit is Terence Tao’s ChatGPT conversation about the recently discovered counterexample to the Jacobian Conjecture, and his observations are sharp:

  • Tao’s messages are very short and respond only to the gist, never point-by-point.
  • The model’s outputs are far more concise than usual, because signaling expertise shunts it into “talking-to-mathematicians” mode rather than “explaining-to-amateurs” mode.
  • Tao pushes back without directly contradicting — he says things like “this looks more complex than I was hoping for.”
  • He almost never takes the model’s advice about where to go next.

Then the load-bearing point: you can’t copy the technique, because Tao can only ask that way because he genuinely understands the mathematics. Pulling the one useful idea out of a multi-paragraph response, and identifying what “looks weird,” is the actual skill.

His inference is directly usable for positioning: “For many tasks, the human is the bottleneck, not the model, because the difficult part is in communicating to the model exactly what kind of solution the human wants. The information is ‘in the model’ already, but it takes a very smart human to pull it out.”

The strongest rebuttal in the thread came from commenter Amekedl: “At the end of the day, it feels and is more like gambling. Even with the recommended expertise and a good approach, don’t delude yourself — you’re simply pulling the lever too, as any novice.” Half right. Experts and novices pull the same lever, but the expert can tell when the result is bad. Which loops straight back to trend #1: judgment is the scarce input.

3. Agent product UX is moving out of your product

Two YC launches this week are worth reading together.

Hoplite (YC S26) does cloud coding agents: one isolated dev environment per thread, the agent reads and edits the repo, runs tests, drives a browser when the app has a preview, and opens a GitHub PR. The founders’ thesis is stated bluntly in their launch post: *”As models improve, developers will end up reviewing less and less code, and will instead focus on reviewing the product output. That means evaluating new user flows, visually verifying that new features look good, that the API works as expected, that the CLI works on Windows, etc. And doing it while running hundreds of agents concurrently.“* They built a custom harness rather than wrapping Codex or Claude Code, and the infrastructure choices are instructive: Temporal for durable workflows, Modal for sandboxes, PlanetScale for the database, everything else AWS.

Armature (also YC-backed) attacks the other half. If you ship an MCP server, a Claude Connector or a ChatGPT App, your user sessions happen inside somebody else’s AI client, not your UI — you cannot see what the user wanted, what the agent was thinking, or where it stalled. Armature reconstructs sessions, clusters them into ranked use cases (including the ones you don’t support yet), and scans for failures, loops and dead ends grouped by root cause. The line in their demo that matters most: this happens “even when every API response was 200 OK.”

Put the two together and the trend is clear: in the agent era, observability shifts from “did the interface error?” to “was the intent satisfied?” Traditional APM is completely blind to that layer.

4. Open source is turning from a value into a feature requirement

Tailscale founder David Crawshaw published a 573-point piece titled Devtools must be open source. The argument is ROI, not ideology.

Five years ago, customizing your own software had questionable returns: you can only write so much in a day, something is always more urgent, and coming back to a personal project a year later for maintenance was “extraordinarily painful.” Agents changed both ends of that equation simultaneously — starting a customization is now trivial, and so is keeping it alive.

He gives two prompt templates you can copy directly. The first: download the source, build it for local use, treat all future changes as source changes replacing the installed version, and record the original motivation in version control. The second, and the important one:

Set up a nightly cron job that executes the prompt: fetch upstream changes and rebase all local changes on top of upstream. Check that the software works as intended and replace the current version.

The inference runs in two directions for a solo builder. Your own toolchain should move decisively toward forkable open source — closed SaaS means you will never fix the interaction that has annoyed you for two years. And maintaining other people’s private forks is itself a business, because rebase conflicts plus regression gating is exactly the work agents can now do and nobody has configured.

Build Directions

Five things to build, with stacks and honest costs. Common thread: none of them sell generation. All of them sell judgment.

Direction 1 — A reproduce-or-refute pipeline for security advisories (top pick this issue)

What: Subscribe to the NVD / GHSA / OSV advisory streams and automatically run JFrog’s four steps on every entry — check out the source at the claimed affected version, compile in an isolated container, run the PoC under a memory sanitizer, audit CPE metadata for self-consistency. Emit a three-state verdict — reproduced / not reproducible / metadata contradictory — with an evidence trail.

Why now: 50+ fabricated advisories entered the world’s most authoritative vulnerability database, with one CVSS revised from 10.0 down to 7.6 after the fact. Organizations bound by “patch all Critical CVEs” clauses now have hallucinated Criticals in their queue. They either burn engineer-days or they buy your tool.

Stack: Docker/Podman for isolated build sandboxes · AddressSanitizer + valgrind for crash adjudication · OSV / NVD / GHSA APIs for the advisory feed · Claude Code or Codex for source-level reasoning like “does this function exist at this tag?” · Temporal or a plain queue for retries and checkpoints · ship as a GitHub Action for OSS maintainers and a SaaS for enterprises.

Cost/time: MVP in 3–5 weeks (start with the C/C++ ecosystem, easiest to automate); $150–600/month infra, compilation being the CPU cost. Free tier for OSS maintainers as distribution, enterprise pricing by dependency count. $199–999/month holds up trivially against one engineer chasing one phantom CVE for half a day.

Direction 2 — Differential verification of agent PRs using production traffic replay

What: Record real production request/response traces as a golden corpus. When an agent opens a PR, replay them, compare old versus new behavior byte-for-byte, and post every deviation as a PR comment. Not “test coverage” — behavioral equivalence evidence.

Why now: Hoplite’s bet is that developers will stop reviewing code and review product output instead. Ankur Sethi’s 461-point post goes to the opposite extreme — he instructs his assistant never to touch files, only to print edits in chat, so he can retype every line by hand and avoid “cognitive debt.” Both paths concede the same thing: manual human review of AI code doesn’t scale. This week’s arXiv paper on COBOL→Java migration (“Locksmith Loop”) supplies the academic answer — validate agent output with a deterministic oracle rather than human eyes, reaching near-complete coverage on two open-source programs and 91.90% branch coverage on an internal production-like COBOL program, with all accepted cases passing deterministic parity checks. Tusk is already shipping a general version (self-described “AI verification layer for coding agents”), which proves the category. Your opening is vertical.

Stack: OpenTelemetry for trace capture · Tusk Drift (open source, github.com/Use-Tusk) or a homegrown replay engine · Hypothesis / fast-check for property-test coverage of the gaps · Docker Compose to stand up the system under test · GitHub App to sit in the PR flow.

Cost/time: 4–7 weeks to a usable v1; $200–800/month infra. Verticals where being wrong costs money — payment reconciliation, insurance underwriting, ERP document flows — sell ten times more easily than a general tool, and $499–2,000/month is cheap in those contexts.

Direction 3 — A session analytics layer for MCP-native and Connector-native products

What: Observability for teams whose product runs inside somebody else’s AI client. Capture sessions, reconstruct user intent, score each session on whether the task was accomplished, cluster failures by root cause, support full replay.

Why now: Armature launched with YC backing, which validates the category while it’s still very early. The real signal is their line about failures happening “even when every API response was 200 OK” — meaning the entire existing APM/logging/error-monitoring stack is blind at this layer. Anywhere existing tools literally cannot see is where new categories form.

Stack: middleware on the MCP server side for interception (ship Node and Python SDKs) · an OpenTelemetry semantic-convention extension · a cheap model (Qwen/GLM class) as LLM-as-judge for scoring, with an expensive model sampling for review · ClickHouse for traces, Postgres for metadata · a session replay timeline in the front end.

Cost/time: 6–8 weeks; $100–400/month (self-hosted ClickHouse keeps this low). Tiered by session volume, $49 entry / $299 team. Caveat: you have a funded competitor. Don’t build the general version — pick a vertical customer set, e.g. only MCP servers serving fintech SaaS.

Direction 4 — Package domain expertise as a steering kit

What: If you have genuine ten-year depth in a narrow field — tax, clinical coding, shipping compliance, semiconductor test, municipal bidding — encode how you interrogate a problem, what you push back on, what “looks weird” as a skill file plus an eval set plus a retrieval corpus. Sell it to people in that industry who use AI but don’t know what to ask.

Why now: Goedecke’s piece articulated this for the first time: everyone holds the same model; the entire delta is the questioner’s domain depth. And domain depth cannot be transmitted through generic prompt tutorials — only through concrete criteria for what counts as anomalous in a specific field. That is precisely what skill files, AGENTS.md and eval sets can carry. This is the one direction this issue that requires almost no code and monetizes pure knowledge asymmetry.

Stack: Claude Code Skills / OpenClaw skill files as the carrier (plain Markdown, no programming) · promptfoo or Inspect for the eval set, used to prove to buyers that accuracy went from X to Y · a light RAG layer (LlamaIndex plus a local vector store) over the corpus · Gumroad or Lemon Squeezy for checkout, no payment infrastructure needed.

Cost/time: 2–3 weeks, mostly spent extracting what’s already in your head; near-zero running cost. Price $99–499 one-time or $29/month with updates. The single go/no-go test: can you produce eval numbers showing your kit actually improved results? If not, don’t ship it.

Direction 5 — Automated maintenance for private forks

What: Productize Crawshaw’s cron prompt. Your customer forked an open-source tool and customized it. Your service pulls upstream nightly, rebases their patches, runs their test gate, lets an agent attempt conflict resolution, and only notifies a human on failure. You’re converting fork maintenance pain into a subscription.

Why now: Crawshaw’s insight is that agents lowered both the cost of customizing and the cost of maintaining, so the number of custom forks is about to explode — and every custom fork is future maintenance debt. Nothing is currently servicing that debt.

Stack: a GitHub App for repo access · nightly cron trigger · Claude Code / Codex for rebase conflict resolution · the customer’s own test suite as the gate (no test suite, no engagement — make that a hard rule) · a structured report to Slack when conflicts can’t be resolved automatically.

Cost/time: 3–4 weeks; cost is mostly agent tokens. Charge $29–149/month per repo. Enter through one specific ecosystem — say, every team running a forked Grafana — because acquisition is far easier than for a generic service.

Risk Factors

  • Your verification tool can hallucinate too. If you use an LLM to judge whether another LLM’s output is correct, the logic is circular. Every verification product that survives has a deterministic core criterion: does it compile, do the tests run, do the bytes match, does the Lean proof check. LLMs can assist the reasoning. They cannot be the final arbiter.
  • The 15% productivity figure means enterprise expectations are deflating. If a customer bought a full AI stack and sees 15% time saved, next year’s budget conversation gets hard. Reframe your value proposition from “efficiency gained” to “loss avoided” — one phantom CVE not chased, one production incident not paid for. That argument survives a skeptical CFO; a productivity percentage does not.
  • Your cost assumptions rest on debt subsidy. $225B issued year-to-date, ~10x YoY growth, $1.65T hidden. That money gets repaid eventually. When you model three years out, include a scenario where token prices rise.
  • The hot directions already have funded competitors. Tusk on verification, Armature on session analytics, Hoplite on cloud agents. The only viable posture for a solo builder is vertical — serve one industry, master one compliance regime, and refuse to build a “general platform.”
  • Smelling like AI is now a negative signal in itself. An HN commenter openly said a YC startup’s landing page “smells” like AI slop. When your product is detecting AI garbage, generating your own site, docs and demo video with one-click AI is a self-inflicted signal mismatch.

Action Recommendations

If you’re just getting started

  • ✅ This week, find the signal-to-noise collapse point in your field. Which information stream is being flooded with generated content while someone downstream is still obligated to take it seriously? That’s your entry.
  • ✅ Start with Direction 4 (expertise kit): two to three weeks, zero infrastructure, and it directly tests whether you actually have a knowledge asymmetry. If you can’t build it, you need domain depth before you need code.
  • ✅ For any verification product, define the deterministic criterion before writing a line of code. If you can’t express “what counts as passing” in machine-executable terms, the product doesn’t exist.
  • ✅ Move your toolchain to forkable open source and set up Crawshaw’s two prompts — local customization plus nightly rebase. Within three months you’ll have earned the operational experience Direction 5 requires.

If you already ship a product

  • ✅ Check whether your product is already being consumed inside someone else’s AI client (MCP, Connectors, Apps). If it is, you are blind to those users right now — instrument minimally yourself before you shop for a tool.
  • ✅ Cut human review of AI code out of your process and replace it with deterministic gates. Record production traces for replay, add property tests, and let humans read only the deviation report. Highest-return change available this week.
  • ✅ Run an inference cost review. Cloudflare’s numbers show FP8 KV caching cuts ~30% off per-token cost and lifts concurrency from 32 to 64. If you self-host, that’s money on the table today.
  • ✅ Ban pasted model output in external communication. Don’t be a meat proxy hitting 1,723 points means the aversion is now industry consensus. The moment your support replies, PR comments or sales emails carry that texture, trust erodes instantly.

What it means

For two years the scarce thing was output. That era ended quietly. A benchmark can now price a whole project, a model can rebuild sixteen thousand lines in an afternoon, and an anonymous repo can inject fifty fabricated security advisories into the world’s most trusted vulnerability database before anyone runs a single proof-of-concept.

Abundance on the generation side has created a shortage on the judgment side — and shortages are where solo businesses get built. The instinct to build another generator is the wrong instinct now; that market is owned by companies with $225 billion of bond issuance behind them. Build the thing that decides whether the generated output is real. Make the core criterion deterministic, pick one vertical where being wrong is expensive, and price against the cost of the mistake rather than the hours saved.

The bottleneck moved. Move with it.
