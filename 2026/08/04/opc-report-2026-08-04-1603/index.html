The Plugin System Is Dead. Ship Something People Can Fork Instead.

The Plugin System Is Dead. Ship Something People Can Fork Instead.

August 4, 2026 — trend monitoring for independent builders and one-person companies

Key Insights

The headline judgment: For most of this week the conversation has been about verification — nobody can check what the machines produce. A 584-point post today pushes past that to something with bigger commercial consequences: once an agent can read and rewrite any codebase, “configurability” stops being a product feature and starts being dead weight.

The author is David Crawshaw — Tailscale co-founder, now building exe.dev and the Shelley agent — and the argument is unusually clean. Plugin APIs, extension systems, and thousand-line config files exist for one reason: reading and modifying a codebase like Vim’s takes a human weeks, so the cost only makes sense amortized across many users. The vendor guesses in advance what you might want to change, exposes those as knobs, and everyone lives inside the vendor’s imagination. Anything outside the knobs, you tolerate or you leave.

He replaces the entire apparatus with two prompts. First: clone the source, build it locally, make the change, record the original motivation in version control. Second — and this is the one that matters — set a nightly cron that fetches upstream, rebases your local changes on top, verifies the thing still works, and replaces the running version. The first prompt makes customization cheap. The second one kills the reason customization was a trap.

Simon Willison, top comment in a 198-comment thread, added the observation that makes this feel less like a hot take and more like a structural shift: the open-source freedom to inspect and modify your tools has, for decades, been a promise almost nobody could cash — including expert programmers, who simply couldn’t justify the hours. LLMs are the first thing that makes it redeemable. His own habit now: “clone x/y from GitHub and tell me how Z works,” several times a day, treating build-from-source as a zero-investment operation.

For a one-person company there are two distinct implications, and they point in opposite directions.

If you sell a product: a “highly configurable” end-user tool — CRM, CMS, task manager, internal ops app — is losing its moat, because a customer can now assemble something that fits exactly instead of contorting their team to fit you.

If you sell a service: the number of custom forks is about to explode, every fork is future maintenance debt, and nobody is currently servicing that debt.

Six numbers that should change your decisions:

  • $20/month for 50 VMs; $25/user/month for teams; $35.84/hour for a 512 vCPU / 2048 GB reserved pool. exe.dev’s public pricing. The line that matters more than any of those: token pricing tracks the model providers’ published rates with no markup. Agent sandboxing is now a printed commodity price. Do not build a business on reselling this layer.
  • Hoplite (YC S26) built its own agent harness rather than wrapping Codex or Claude Code — explicitly so it doesn’t have to “wait for Anthropic and OpenAI to catch up.” Infrastructure: AWS, plus Temporal for durable workflows, Modal for sandboxes, Planetscale for the database. Their stated 6–12 month bet is worth copying into your roadmap: developers will review less and less code and increasingly review product output — does the new user flow work, does it look right, does the API behave, does the CLI run on Windows.
  • FP8 KV cache: 686,000 → 1.37M resident context tokens, concurrency ceiling 32 → 64, peak throughput +41%, cost per token −30%. Cloudflare’s measured numbers on Kimi K2.6 on disaggregated H200s. Note the shape of the win: at any single concurrency level FP8 is a few percent slower per token. All of the gain comes from how many requests fit at once.
  • MiniMax H3 shipped open weights: 2K output, 15-second clips, native stereo audio generated in the same pass, runs locally on a 3060, day-zero ComfyUI support. First time open weights reach finished-with-sound video. Content-side solo operators can now own their inference stack.
  • 15% for senior engineers, 25% for juniors. Bjorn Roche’s hour-by-hour breakdown: a senior spends only 1.5 hours a day writing new code, so even a 3x speedup saves 1.25 hours (8h → 6.75h). Use this as the ceiling on any ROI you promise a client.
  • 10,390 stars in six days / 1,565 stars in six days. yc-software/qm (a multiplayer agent harness, created July 29) and microsoft/skill-recorder — which records your on-screen work session, uses the Copilot CLI to reconstruct it as intent plus ordered steps, and builds a reusable Skill. Watch the second one closely: workflow itself is becoming a tradeable artifact.

Market Trends

One: customization replaced configuration, and forks became the new plugins

Unpack Crawshaw’s argument and it describes a cost inversion. Extension APIs and YAML mountains exist because editing source was expensive. Remove that expense and the entire abstraction layer is overhead — overhead that also constrains what users can do to whatever the vendor anticipated.

His worked example is specific enough to be useful. He has a side tool, meat.dev, that takes a diff and uses an LLM to strip out everything unimportant — import blocks, nil checks, error handling — leaving only the parts worth a human’s attention. He wanted it inside his agent client, Shelley, and he wanted commits pre-processed in the background the moment they’re created, so the diff is ready when he arrives. He got all of that from one prompt. His own assessment of the alternative: pushing the same feature through the VS Code extension API or vimdiff would be “nigh-on impossible” for the background pre-processing part — not because the work is hard, but because the extension points are the wrong shape.

His summary line is the one to remember: “That is the fundamental difference between classic configuration/customization and agent-driven personalization: you can do so much more.”

The dividing line this creates: closed source now means non-customizable

Crawshaw names names. The same skill-file technique applies to open agents like Codex and Pi — so much so that he wonders aloud why Pi bothers with an extension system, since “the source code is the extension system.” Claude Code is where you hit a wall, because it’s closed. It offers plenty of old-fashioned hooks, and his verdict is blunt: hopefully how you want an agent to work fits inside them; if not, switch to an agent that lets you personalize it.

For your own tooling decisions this is now a practical risk item, not an ideological one: anything you plan to embed deeply in your workflow for years is riskier closed than open.

The comment thread supplied two real boundaries worth writing down. First, a founder building in the same space (boxes.dev) forked codex last December, added his own plan mode, and reports it was “fun and satisfying” but “a bit of a pain to keep updated” — and that was eight months and one model generation ago. The pain is falling, not gone. Second, someone flagged that LLMs are functioning as license-laundering machines, citing a real case where a project decided that after sweeping LLM-driven architectural changes the codebase was no longer a derivative work and relicensed from GPL to MIT. If you plan to run a fork business, decide where you stand on that grey zone before your first customer, not after.

Two: cloud agent sandboxes — the category is real, and the price is now public

Two data points landed today that should be read together.

exe.dev’s pricing page: $20/month personal (50 VMs, 100 GB pooled disk, 200 GB transfer), $25/user/month team (50 VMs per user, 250 GB transfer, SSO and admin), $35.84/hour for a reserved 512 vCPU / 2048 GB pool. Overages at $0.08/GB/month disk and $0.05/GB/month transfer. And explicitly: token pricing tracks provider published rates, no markup.

Hoplite’s Launch HN: YC S26, onboarding ports your local setup — sessions, memories, MCP servers — into the cloud, $100 in free credits with code HACKERNEWS, and you can connect your own Codex subscription to use OpenAI models through it.

Together they say something unsentimental: “isolated environments for agents” has gone from technical challenge to shelf-priced commodity, and the shelf price is low. If your pitch is “we run your agents,” you are competing against $20/month for fifty VMs with zero token margin.

The opportunity sits above the sandbox, not in it

Hoplite’s founder openly concedes that using them means giving up infrastructure freedom in exchange for easier onboarding and a more polished experience. A commenter immediately countered that Claude Code’s mobile app plus a self-hosted docker-compose with a Playwright container gets him eighty percent of it, plus a real browser.

That exchange maps the value layers precisely. The sandbox is a commodity; the verification evidence on top of it is the product. The most commercially honest sentence on Hoplite’s site is that the agent runs tests, drives a browser when there’s a preview, and gives you verification evidence to review. That last phrase is the part anyone will pay for.

Three: open weights reach the media layer while inference keeps getting cheaper

MiniMax H3 dropped with open weights and had native ComfyUI support the same morning. The capability list is worth reading item by item: text-to-video, image-to-video, first-and-last-frame control, and reference-to-video — supply a reference clip and it carries a camera move, a performance, or a cutting rhythm onto a different subject. Output to 2K, up to 15 seconds, and audio generated in the same pass as the video, in native stereo, not bolted on afterward. MiniMax’s third-generation video model and the first they’ve released open. ComfyUI says it’s optimized enough to run locally on a 3060.

On the text side, costs kept falling. Cloudflare published its three techniques for serving Kimi and GLM at scale, and the KV cache quantization numbers are the most transferable. Dropping the cache from BF16 to FP8 (e4m3) takes Kimi K2.6 from roughly 686,000 resident context tokens to about 1.37 million, lifts the concurrency ceiling from 32 to 64, and delivers peak throughput of 2,192 tok/s — 41% above BF16’s peak, at roughly 30% lower cost per token. They are careful to note this is not a speed win: FP8 is a few percent slower per token at every fixed concurrency level, and BF16 simply runs out of memory at 33 concurrent requests. They also split prefill and decode into separate pools and leave prefill in BF16, since prefill is compute-bound rather than memory-bound.

Hardware floors keep dropping too. AirLLM (27,674 stars) runs 70B inference on a single 4 GB GPU. Swiftlet demonstrates an 80B Qwen in 4.3 GB of RAM on a Mac and a 35B on an iPhone. And sqliteai/waste — created eight days ago, already 1,589 stars — goes furthest: a dependency-free embeddable C engine that streams activated weights straight off NVMe to run the full 2.78-trillion-parameter Kimi K3 on machines that cannot hold it.

Don’t misread this trend

The shared cost of all these approaches is latency, not capability. Swiftlet’s own testing shows a 10,000-token prefill taking roughly 30 minutes. The correct use is not “I’ll build a realtime product on this.” It’s move batch jobs, overnight runs, and privacy-sensitive work onto local inference, and spend the savings on the small fraction of calls that genuinely need low latency.

Build Directions

Five directions, one common thread: now that customization is cheap, the money moved from selling features to selling fit and selling maintenance.

Direction 1 — Sell a forkable vertical app (top pick this issue)

What: Pick a narrow vertical — clinic scheduling, freight forwarding documentation, solo-practice case management, small-factory production planning. Build an application that does just enough, ship the source to the customer, and include an AGENTS.md plus skill files explaining how to read the codebase, what’s safe to change, and how to verify a change. When they want another field, a different workflow, a new report, their agent does it. You charge for hosting, upstream sync, and being the one who fixes it when it breaks.

Why now: Crawshaw’s line — “For end-user products to make sense in a company today, they need to be personalizable. Which means we need the source code.” — lands hardest on vertical SaaS, whose classic death is that every customer wants something slightly different. The old defenses were saying no or adding another config knob. Now you can say “change it yourself,” and that’s the selling point.

Stack: boring, readable technology for the app itself (Next.js/Django + Postgres — the more unremarkable, the easier agents modify it) · AGENTS.md + worked customization examples + a minimal test suite as guardrail, in-repo · hosting on Modal / Fly / exe.dev at $20/month, don’t self-build · nightly cron plus Codex or Claude Code for upstream rebase · source-available licensing (BSL / Fair Source) to retain commercial rights.

Cost/time: MVP in 6–8 weeks; $15–60/month hosting per customer. Price $150–600/month per customer plus a setup fee. The real barrier isn’t code — it’s knowing what the paperwork in that industry actually looks like. Only build for an industry you’ve worked in.

Direction 2 — Managed maintenance for private forks

What: Productize Crawshaw’s cron prompt. Your customer forked an open-source tool and customized it. You pull upstream nightly, rebase their patches, run their test suite, let an agent attempt conflict resolution, and only escalate to a human on failure. You are converting fork-maintenance pain into a subscription.

Why now: This is the inevitable byproduct of trend one — fork count explodes, maintenance debt follows, nobody services it. The pain sample is already in the thread (“I forked codex in ~Dec… it ended up being a bit of a pain to keep updated”). The elegant part: your market grows linearly with the trend itself. Every new convert to personalized software is a future customer.

Stack: GitHub App for repo access · nightly cron trigger · Codex / Claude Code for rebase conflict resolution · the customer’s own test suite as the sole gate — no test suite, no engagement, make it a hard rule · structured Slack report when conflicts can’t resolve · run the workers on Modal or exe.dev’s by-the-second sandboxes.

Cost/time: 3–4 weeks; cost is mostly agent tokens. Price $29–149/month per repo. Enter through one specific ecosystem — every team running a forked Grafana, or everyone who’s hacked up n8n — because acquisition is an order of magnitude easier than for a generic service.

Direction 3 — An open-weight pipeline for finished video with sound

What: Use MiniMax H3 to build an inputs-to-finished-clip pipeline for one specific industry. Not a general video tool — templated industry delivery: 30-second narrated property listings, single-product e-commerce spots, course clips, restaurant walk-throughs. Customer uploads assets and bullet points, you deliver the cut.

Why now: H3 is the first release to open-weight native stereo, 2K output, and reference-video motion transfer together, with same-day ComfyUI support optimized down to a 3060. That means your marginal cost is electricity rather than an API invoice — the only structure in which content businesses currently produce real gross margin. Teams doing generation through hosted APIs are handing their profit upstream.

Stack: ComfyUI as the orchestration layer (the workflow graph is your asset) · MiniMax H3 weights deployed locally, 3060/4090-class GPU floor · first-and-last-frame plus reference video for style consistency · frontend is a form and a queue page, nothing more · deliver via file links, don’t build a player.

Cost/time: 4–6 weeks, mostly spent tuning workflows and templates rather than writing code; $400–2,000 one-time hardware or hourly cloud GPU. Price $30–150 per clip or $299–999/month for N clips. The moat is template quality and industry taste, not technology — so start by studying what that industry’s current videos look like.

Direction 4 — Record expert operators and sell the skill pack

What: Find a genuine domain expert — customs broker, clinical coder, tax specialist, bid writer — record their actual screen workflow, reconstruct it as intent plus ordered steps, and package it as agent-executable skill files plus an eval set. Sell it to people in that industry who use AI but don’t know what to ask.

Why now: microsoft/skill-recorder hit 1,565 stars in six days doing exactly the tooling layer for this — a large vendor is validating the premise that workflow can be captured as an artifact. The demand side came from an 835-point post, Sean Goedecke’s LLMs reward expertise, whose argument is that everyone holds the same model and the entire delta is the questioner’s domain depth. His illustration is Terence Tao’s ChatGPT transcript on the Jacobian Conjecture counterexample: short messages, expertise signalled so the model drops into talking-to-mathematicians mode, pushback phrased as “this looks more complex than I was hoping for” rather than direct contradiction, and Tao almost never taking the model’s suggestion about where to go next. You cannot transmit that through a generic prompting tutorial — only through concrete criteria for what counts as anomalous in a specific field. Which is exactly what a skill file can carry.

Stack: skill-recorder or manual capture (screen recording + transcript + structuring) · Claude Code Skills / OpenClaw skill files as the carrier — plain Markdown, no programming · promptfoo or Inspect for the eval set, used to prove to buyers that accuracy went from X to Y · light RAG (LlamaIndex + local vector store) over the domain corpus · Gumroad or Lemon Squeezy for checkout.

Cost/time: 2–3 weeks, most of it spent extracting what’s already in the expert’s head; near-zero running cost. Price $99–499 one-time or $29/month with updates. Single go/no-go test: can you produce eval numbers? If not, don’t ship.

Direction 5 — De-SaaS migrations: replace the configurable product with a fork that fits

What: Take a very specific job: move a small team off a per-seat SaaS — CRM, CMS, task manager, knowledge base, helpdesk — onto a personalized fork of an open-source equivalent, reshaped around their actual process, data migrated, nightly sync configured. One-time conversion fee, then monthly maintenance.

Why now: Crawshaw poses the question directly: “Why would an engineering team purchase an extremely configurable task manager (or a CMS or CRM), spend time learning and configuring it, and contort their team to its limits, when they can assemble just the features they want from common building blocks?” And the raw material is arriving — trycompai/crm, an “open-source, agentic-first CRM,” is at 3,700 stars, part of a wave of projects born expecting to be forked. This pitch also has a hard commercial anchor most consulting lacks: the per-seat subscription you eliminate is a number you can put in the proposal.

Stack: target open-source projects (lock to 1–2 per category, don’t take everything) · Claude Code / Codex for the reshaping work · data migration written as re-runnable scripts, never manual · hosting on the customer’s own cloud or Fly/Hetzner · upstream sync reuses Direction 2’s cron pipeline (the two business lines share infrastructure).

Cost/time: 2–4 weeks per engagement. Price $3,000–15,000 one-time plus $200–800/month maintenance. Critical risk control: write into the contract that scope is fixed to the feature inventory as of migration day, or scope creep will eat the margin.

Risk Factors

  • Fork maintenance debt compounds; it isn’t a one-time cost. The developer who forked codex in December was honest about it — fun, but “a bit of a pain to keep updated.” Directions 1, 2 and 5 all mean buying that pain from someone else. Price for the month upstream does a major refactor, not for an average month.
  • “Does it seem to work?” stops being an acceptable bar the moment money changes hands. Crawshaw explicitly says single-user software can substitute that question for careful code review. That tolerance does not transfer along with the software when you deliver it to a paying customer. If you sell forks, you ship deterministic gates — test suites, replay comparison — or your first production incident erases both the margin and the reputation.
  • The licensing grey zone is widening, and widening isn’t the same as safe. There’s already a documented case of a project deciding that post-LLM architectural rewrites made it non-derivative and relicensing GPL to MIT. Running a commercial fork service means checking the license class before you accept the engagement — route around AGPL/GPL projects or make the customer the one who holds them.
  • There is no margin left in the sandbox and compute layer. exe.dev sells 50 VMs for $20/month and states plainly that tokens pass through at provider rates with no markup. Any model that amounts to “we run your agents” or “we call the API for you” needs re-underwriting this week. Your revenue has to come from outcomes, evidence, or fit — not from resale.

Action Recommendations

If you’re just starting out

  • ✅ Run Crawshaw’s two prompts on yourself this week. Pick an open-source tool you use daily, have an agent clone it, add the one small feature you’ve always wanted, and wire up the nightly rebase. It’s the cheapest possible validation of Directions 1, 2 and 5 — and the entry ticket to all three.
  • ✅ Make Direction 4 your first product. Two to three weeks, no infrastructure, and it directly tests whether you hold a real knowledge asymmetry. If you can’t produce eval numbers, the answer is to go deeper into a domain, not to write more code.
  • ✅ Weight “open and forkable” as heavily as features when choosing tools. For anything you’ll embed deeply — agent, editor, orchestrator — closed source is a risk that bites in six months.
  • ✅ If you work on the content side, run the MiniMax H3 ComfyUI workflow this week. Open weights, 3060-capable, native stereo — the first time all three conditions have held simultaneously.

If you already have a product

  • ✅ Count your config options, then count how many are actually used. If a meaningful share of your engineering went into configurability, reallocate it toward documentation and test guardrails that make your product safely modifiable by a customer’s agent. Better return.
  • ✅ Replace “human reviews the AI’s code” with “human reviews the product output.” Hoplite is commercializing this bet; you don’t have to buy from them, but change the process — make agents deliver verification evidence (test results, browser screenshots, API diffs) and have humans read only the deviations.
  • ✅ Do an FP8 KV cache review this week if you self-host. Cloudflare’s numbers are concurrency 32 → 64 and cost per token down ~30%. No model change, no product change — pure margin.
  • ✅ Write a “if you want to modify this, start here” document for your top customers. Whether or not you’re open source, they’re already pointing agents at your product. Give them guardrails now instead of debugging their changes later.

What It Means

For two years the strategic question was “what can AI build for me?” This week’s version is sharper and less comfortable: what is still worth charging for once building is cheap?

Crawshaw’s answer, read commercially, is that fit and continuity are the last scarce goods. Anyone can now have software shaped exactly to their process — but somebody has to keep that shape alive as upstream moves, and somebody has to prove it still works. Those are subscriptions, and almost nobody is selling them.

Everything below that line is being priced to zero in public: sandboxes at $20/month, tokens passed through at cost, frontier-class weights running on a gaming GPU. Don’t build where the price is printed. Build where the maintenance is.
